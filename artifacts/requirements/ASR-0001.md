# ASR-0001

**Priority:** 1  
**Status:** Active  
**Created:** 2026-06-14  
**Updated:** 2026-06-14  

## Requirement

The system must not alter source data values during ingestion, storage, or query. An "ingest → rearrange columns → export" roundtrip must produce cell values identical to the original, even though layout, column order, and row selection may differ. This is critical because TableFlip handles financial data where value fidelity is non-negotiable.

**Scope:** Raw user files (XLSX, CSV, .rcjson) at ingestion point, and their persisted representation in the SQLite database (state.tables).

**Prohibited:**
- Row loss during import
- Silent type coercion of cell values (e.g., "00123" → 123; boolean TRUE → 1)
- SQL mutations (INSERT, UPDATE, DELETE, DROP, ALTER, CREATE INDEX) on source tables initiated by the system
- Metadata injection that overwrites or collides with source column names

**Permitted:**
- Column projection, filtering, sorting, aggregation (all produce derived result sets)
- Injection of _-prefixed metadata columns (_rowno, _band_id, _row_type, etc.) — reserved namespace that cannot collide with user columns
- Merged cell expansion during XLSX ingestion (faithful to visual intent)
- User-initiated row exclusions stored in separate excludedRows set — source rows untouched
- User-initiated table removal and re-import

**Known violations (to be corrected):**
- core/sqldb.ts: coerceForSQL() converts numeric strings to numbers — silent type coercion
- tests/core/sqldb.test.ts: test expects coercing behavior

**Edge cases requiring explicit design decisions:**
- CSV has no types — "01234" is text; roundtrip fidelity requires preserving as text
- Excel date serials (45292 → Date → string) are irreversible; define what "identical" means for dates
- Boolean → numeric coercion: roundtrip produces 1 not TRUE
- Empty cell vs. null equivalence
- Merged cell export: original merge structure lost, duplicated values instead
- Floating-point precision: IEEE 754 roundtrip should be exact, but text like 1e10 needs verification

## Notes

Foundation ASR. Sets the integrity standard for the entire artifact system. Violations were found on first validation pass — coerceForSQL() and its tests — confirming the ASR has teeth. These will be corrected in a follow-up task.
